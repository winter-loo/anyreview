# 视频评审设计访谈

日期：2026-09-10。状态：已实现并完成本地服务部署与验收。

## 用户已提出的目标

- 使用 review 打开 AI 生成的视频，观看并指出修改意见。
- 支持时间点、连续时间范围、多个独立时间点三种标注。
- 视频页提供独立时间进度控制条，先选位置，再填写评论。
- AI 能取得评论对应的时间和具体帧位置。
- 支持逐帧定位、倍速播放、时间 / 帧数两种显示方式。
- 帧数模式：左右方向键移动一帧，Shift + 左右移动十帧。
- 时间模式：默认速度下上键为 2×、下键为 0.5×；已有速度设置后，上下键按用户描述加减 1×。

## 最终交互约定

1. 打开单个本地视频，完成实际帧索引预处理后进行精确评审。
2. 点击时间轴暂停视频、添加时间点并打开评论面板；继续点击默认向同一条评论追加点。
3. 选中一次性的“范围”，将最近新增点和下一次点击的位置替换为按时间排序的范围；一条评论可混合多个点和范围。
4. 用户输入意见并保存；位置标签支持回看和移除。保存后保持暂停，手机选点不主动弹出键盘。
5. 拖动播放头、逐帧按钮和键盘支持单纯定位；“添加当前帧”将定位结果加入评论。时间/帧显示切换和临时倍速遵循前述规则。
6. 点击“提交给 AI”交付反馈批次；AI 取得视频身份、评论、时间和实际帧位置，无截图。评审本身不执行剪辑或自动启动 AI。

## 实现依据

- 使用 [ffprobe 的逐帧输出](https://ffmpeg.org/ffprobe.html)建立实际帧时间索引，不用平均帧率推算。索引异步排队生成，页面显示进度，结果随快照缓存。
- 播放时使用浏览器 [requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback) 的 `mediaTime` 更新帧位置；暂停定位时 seek 到目标帧区间内部，避免时间边界舍入。
- 视频采用 HTTP byte ranges 和流式传输，快照与 AI 原文件下载也避免整段视频驻留内存。
- 手机播放头的拖动手柄位于选点区域上方，避免手柄拦截相邻时间点的点击。

轨道上方（含播放头上半部）点击或拖动只定位到最近帧；轨道点击才添加评论位置。轨道拖动仍用于平移，双指仍用于缩放。已有评论草稿时，上方定位不追加位置。浏览器已验证上方点击/拖动、光标点击、轨道新增及草稿保持；类型检查通过。

## 渐进式帧定位（2026-09-10）

- 视频元数据加载后即可播放和时间标注；浏览器先按 30 fps 临时估算，收到服务器轻量元数据后使用报告帧率。页面明确显示估算状态和后台校准进度。
- 精确帧索引继续后台生成；完成后不暂停或跳转视频，切换到真实帧位置。失败时仍保留估算定位。
- 新标注保存稳定时间锚点，时间范围保存开始时间与结束时间（不含）；服务器允许精确索引完成前保存与提交，输出 `framePrecision: estimated`。索引完成后使用真实帧重新解析帧号，保留时间和正文。旧版仅帧号标注仍受支持。
- 已提交批次重新读取时可获得校正帧号，但不会仅因校准自动产生新批次。
- 验证：可变帧率视频在索引前保存/提交、索引后时间不变；浏览器模拟索引延迟，立即播放、估算提示、播放中切换、草稿跨刷新均通过。
